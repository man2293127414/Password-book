# PC 局域网 Web 客户端设计

## 1. 目标与边界

本阶段补齐由 Android App 内置局域网服务提供的 PC Web 页面。用户在手机主动开启 PC 访问后，PC 通过 `http://<手机局域网地址>:8080` 打开页面、输入六位访问码，并在本次临时会话中管理手机内的密码库。

本阶段必须实现：

- 访问码配对和明确的连接状态。
- 查看、搜索、新增、修改、删除及复制密码记录。
- 创建、重命名及删除分类和标签。
- 密码默认遮挡，点击后只显示当前记录。
- 手机与 PC 同时修改时进行版本冲突提示。
- 服务停止、超时或网络变化后清除页面中的会话和密码数据。

本阶段不实现：

- PC 导入、导出或清空全部数据。
- 多 PC 会话、长期信任设备或账号系统。
- 浏览器扩展、额外 PC 程序、证书安装或云同步。
- `localStorage`、`sessionStorage`、`IndexedDB`、Service Worker 或其他密码库持久化。

## 2. 技术路线

### 2.1 选择

采用随 APK 离线打包的纯 JavaScript 密码库，在普通局域网 HTTP 页面中执行 P-256 ECDH、HKDF-SHA-256 和 AES-256-GCM。依赖固定为：

- `@noble/curves@2.4.0`
- `@noble/hashes@2.4.0`
- `@noble/ciphers@2.4.0`

使用官方 npm 注册表发布的 2.4.0 ESM 文件。三个包的发布版本、tarball URL、npm `dist.integrity`、tarball SHA-256、每个随 APK 打包文件的 SHA-256 和 MIT 许可证都记录在仓库；GitHub Release 标签继续作为上游签名版本证据。依赖文件直接提交到 Android assets，构建和运行时都不执行 npm 安装，也不从 CDN、npm 或其他远端下载代码。版本升级必须是单独、可审查的变更，并重新运行 Java/JavaScript 互操作测试。

2.4.0 的 GitHub Release 和 npm 包均已核对，但该版本没有可下载或包内 standalone 单文件，所以不把不存在的 standalone 地址写入实现。浏览器通过内联 import map 加载本地 `node_modules/@noble/` ESM；同一目录结构也让 Node 内置 test runner 在不安装依赖的情况下直接运行互操作测试。

### 2.2 未选择的路线

- 不使用原生 Web Crypto：`crypto.subtle` 仅在 secure context 可用，普通私有局域网 IP 的 HTTP 页面不满足该条件。
- 不增加手机自签名 HTTPS：这会要求用户处理证书警告或安装证书，违背首版简单使用要求。
- 不发送明文业务数据：访问码、账号、密码和备注必须继续使用现有 LAN v1 协议保护。
- 不自行实现椭圆曲线、HKDF 或 AES-GCM。

## 3. 页面组成

Android assets 中的 PC 页面拆分为职责明确的静态文件：

- `index.html`：可访问的页面结构、配对界面和应用容器。
- `styles.css`：与手机端一致的色彩、间距、卡片、按钮和状态样式。
- `app.mjs`：页面状态、事件绑定、渲染和用户提示。
- `lan-client.mjs`：配对流程、请求队列、API command 和错误映射。
- `lan-crypto.mjs`：LAN v1 所需的编码、密钥派生及 envelope 加解密适配。
- `vault-ui-model.mjs`：搜索、筛选、表单映射和不依赖 DOM 的纯逻辑。
- `node_modules/@noble/`：固定版本的 Noble ESM 运行时文件、各包 `package.json` 和 MIT 许可证；这里只是随 APK 提交的 vendor 目录，不执行包管理器安装。
- `vendor-manifest.json`：上游 tarball 来源、完整性、文件散列和许可证清单，不向浏览器路由公开。
- `runtime-assets.tsv`：浏览器可请求的精确文件与 MIME 白名单，由 Android 服务读取；清单自身不向浏览器公开。

NanoHTTPD 只提供上述明确白名单文件，不实现目录遍历、任意 assets 读取或通用静态文件服务器。所有静态响应继续设置 `Cache-Control: no-store` 和 `X-Content-Type-Options: nosniff`。

## 4. 配对与请求数据流

### 4.1 配对

1. 页面获取 `/api/v1/pairing-info`。
2. 浏览器在内存中生成临时 P-256 密钥对。
3. 用户输入六位访问码。
4. 页面通过 P-256 ECDH 和 HKDF 派生 handshake key，使用 AES-GCM 加密访问码。
5. 页面提交 `/api/v1/pairing-submit`，解密返回的 `sessionId`，再派生请求和响应方向密钥。
6. 页面立即请求 `snapshot`，进入主界面。

页面不在 URL、控制台、DOM 属性或持久化存储中保存访问码。配对成功后清空输入框和对应字符串引用。配对失败统一显示“访问码错误或已失效”，不展示剩余尝试次数。

### 4.2 会话请求

`lan-client.mjs` 维护一个串行 Promise 队列。每个请求按入队顺序分配严格递增 counter、加密 command、提交 `/api/v1/vault`、校验响应 counter 并解密结果。任何请求都不能绕过该队列。

页面只在内存中保存最新 `VaultSnapshot`。每次 mutation 成功后统一重新请求 `snapshot` 再渲染，不在 PC 端复制手机业务层的分类、标签关联更新规则；不得建立第二份持久化数据库。

## 5. PC 界面与交互

### 5.1 配对页

配对页包含产品名称、六位数字输入框、连接按钮和简短提示。加载、错误和已断开状态使用同一区域展示，避免复杂向导。

### 5.2 主界面

桌面布局采用左侧栏、顶部搜索区和右侧表格式列表：

- 左侧栏：全部密码、未分类、分类、标签，以及分类/标签管理入口。
- 顶部：搜索框、当前筛选名称、刷新和新增密码按钮。
- 列表：名称、账号、分类/标签、修改时间和快捷操作。
- 小窗口下改为卡片列表，但保持相同字段和操作顺序。

搜索范围为名称、账号、网址、分类名称和标签名称，不匹配密码或备注。分类和标签筛选可以与搜索同时生效。

### 5.3 密码操作

- 密码默认固定显示 `••••••••`。
- 点击眼睛只切换当前记录，不影响其他记录。
- 复制账号或密码无需先显示，成功后给出短提示。
- 页面不读取或展示系统剪贴板现有内容，不记录复制内容。

### 5.4 新增、编辑和删除

新增和编辑共用一个表单，字段与手机端一致：名称、账号、密码、网址、分类、标签和备注。保存前进行基础必填校验，最终规则仍由手机端 `VaultService` 决定。

删除密码、分类或标签必须二次确认。删除分类仅使原记录变为未分类；删除标签仅解除关联；这些语义由手机业务层保证。

## 6. 冲突、错误与断开

- `VALIDATION`：保留表单内容并显示可理解的校验提示。
- `NOT_FOUND`：提示记录已不存在并刷新快照。
- `STALE_VERSION`：提示“记录已变化，请刷新后重试”，随后重新获取快照，不得自动覆盖。
- `BAD_REQUEST` 或 `INTERNAL`：显示通用失败提示，不展示服务端堆栈或敏感数据。
- `UNAUTHORIZED`、`DISCONNECTED`、解密失败、重放响应、网络失败：立即进入断开状态。

进入断开状态时必须：

1. 停止继续发送排队请求。
2. 将会话密钥字节数组覆写为零并释放引用。
3. 清空内存快照、编辑表单、已显示密码和敏感 DOM 文本。
4. 显示“与手机连接已断开，请在手机重新开启 PC 访问”。

页面关闭和 `pagehide` 时执行相同的本地清理。JavaScript 无法保证垃圾回收时间，因此文档只承诺主动覆写可控字节数组并移除引用，不宣称浏览器内存可被绝对即时擦除。

## 7. 安全约束

- 所有 vault command 和响应继续使用现有 LAN v1 envelope 加密及认证。
- 不记录访问码、sessionId、密钥、账号、密码或备注。
- 不把敏感值放入 URL、错误堆栈文本、HTML data 属性或分析事件。
- 禁止 CDN、远程字体、遥测和第三方网络请求。
- Noble 文件只从清单记录的官方 npm 发布包更新；引入或升级时验证 npm `dist.integrity` 与 tarball SHA-256，常规测试验证每个已提交文件的 SHA-256。
- 未认证端点和静态文件不得包含 vault 数量、名称、分类或标签信息。
- 本阶段威胁模型仍假设个人可信 PC 和可信局域网；主动替换手机所提供页面或公钥的攻击者不在首版防护范围内。

## 8. 测试与验收

### 8.1 自动测试

- 使用现有协议向量验证 Noble 与 Java 的 P-256 ECDH、HKDF、AES-GCM 结果一致。
- 验证配对请求、会话响应、counter 分配、响应重放和篡改拒绝。
- 验证请求队列不会并发发送或复用 counter。
- 对 `vault-ui-model.mjs` 测试搜索、分类/标签筛选、命令生成和版本冲突状态。
- 验证静态文件白名单、正确 MIME、`no-store`、`nosniff` 和未知路径 404。
- 验证 vendor 版本、SHA-256、许可证和 APK assets 打包。
- 继续运行核心 Java、LAN HTTP、浏览器互操作和 Android instrumentation 测试。

测试使用现有 Node 内置 test runner，不为了 DOM 测试增加 jsdom、Playwright 或其他生产依赖。页面状态和纯逻辑通过依赖注入保持可测试，实际浏览器交互作为集成验收。

### 8.2 集成验收

- Chrome 和 Edge 在普通局域网 HTTP 地址上能够完成配对及所有定义的 PC 操作。
- 同一 Wi-Fi 和手机热点各验证一次。
- 手机与 PC 同时编辑同一记录时出现冲突提示。
- 服务停止、超时、切换网络和导入/清空后，PC 明确断开且不能继续读取或写入。
- 页面刷新后必须重新配对，浏览器中不存在可恢复的密码库副本。

本机没有 Android SDK、模拟器和物理设备时，只能完成代码及 Node/Java 自动测试；真实 Chrome/Edge、Wi-Fi 和热点结果必须明确记录为后续云构建或设备验收证据，不能虚报为已通过。

## 9. 完成标准

- PC 页面完成规格定义的凭据、分类和标签功能。
- 普通局域网 HTTP 下不依赖原生 Web Crypto、证书、扩展或额外程序。
- 三个 Noble 依赖严格固定为已批准版本并通过来源与散列校验。
- 无浏览器持久化、缓存或第三方网络请求。
- 自动测试通过，独立代码审查无 Critical 或 Important 问题。
- 未执行的真实设备和浏览器验收被清晰列为 deferred evidence。
