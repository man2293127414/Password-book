# 离线密码记录器产品设计

- 日期：2026-08-27
- 状态：已通过用户审核，进入实现阶段
- 产品形态：Android 原生应用 + 手机内置局域网 Web 页面
- 使用对象：单用户、个人自用

## 1. 产品概述

本产品是一款个人使用的 Android 离线密码记录器。手机是唯一数据源和唯一持久化主库。除用户主动导出的加密备份文件外，所有密码记录只保存在手机本地。用户可以直接在手机上管理密码，也可以在手机与 PC 位于同一 Wi-Fi，或 PC 连接手机热点时，临时开启局域网访问，通过 PC 浏览器管理手机中的数据。

PC 浏览器不是同步端，不持有独立密码库。手机停止局域网服务后，PC 会话立即失效。

## 2. 产品目标

首版需要实现以下目标：

1. 在 Android 手机上保存和管理个人账号密码。
2. 支持名称、账号、网址、分类和标签搜索。
3. 支持分类和标签管理。
4. 默认遮挡密码，用户明确点击后才显示。
5. 支持同一局域网内的 PC 浏览器临时访问。
6. PC 端支持查看、搜索、新增、修改、删除和复制密码。
7. 支持使用独立备份密码进行加密导入和导出。
8. 不依赖账号、云服务或互联网。
9. 手机始终是唯一数据源。

## 3. 首版非目标

首版不实现：

- 应用内密码锁、忘记密码和恢复码
- 指纹或面容解锁
- 云同步、在线账号和互联网远程访问
- 多用户、家庭共享和多密码库
- 多台 PC 同时访问
- 长期信任某台 PC
- 浏览器扩展
- Android 自动填充
- TOTP 动态验证码
- 密码生成器
- 密码强度和重复密码检测
- 密码历史
- 回收站
- 附件和安全笔记
- 操作审计日志
- CSV、Excel 或明文 JSON 导入导出
- PC 端导入导出

这些功能可以在首版稳定后重新评估，不为其提前设计复杂扩展结构。

## 4. 已选实现路线

采用“Android 原生界面 + 手机内置 Web 服务”方案。

### 4.1 Android 原生界面

负责：

- 密码列表和详情
- 新增、编辑和删除
- 搜索、分类和标签筛选
- 分类与标签管理
- PC 访问的开启和停止
- 备份导入导出
- 简单设置

首版不显示应用内解锁页面。是否需要额外验证完全交由手机系统的应用锁功能决定。

### 4.2 本地密码库

手机本地数据库是唯一持久化数据源。手机界面和 PC Web 页面都通过同一业务层访问该数据库，避免形成两套数据。

数据库在设备上加密保存，使用设备绑定的安全密钥完成透明加解密。用户日常使用时不需要输入额外密码。系统自动云备份不得包含数据库、设备密钥或其他敏感文件。

### 4.3 局域网服务

局域网服务仅在用户主动开启 PC 访问时运行，负责：

- 提供打包在 App 内的 PC 静态页面
- 验证 6 位临时访问码
- 建立并维护单个 PC 会话
- 提供密码、分类和标签的数据接口
- 将 PC 操作写入手机本地数据库
- 在停止、超时或网络变化时撤销会话

服务不得依赖公网接口、远程服务器、第三方 CDN 或外部字体资源。

### 4.4 PC Web 页面

PC 页面由手机提供，负责展示和编辑手机中的数据。它不建立独立数据库，也不提供数据同步功能。

页面不得使用 `localStorage`、`IndexedDB` 或 Service Worker 持久化密码记录。页面和接口响应需要禁止浏览器缓存敏感数据。会话期间不可避免地需要在浏览器内存和系统剪贴板中暂存用户主动查看或复制的内容，但会话结束后不能继续访问手机密码库。

### 4.5 备份模块

负责生成和读取应用自己的加密备份格式。备份通过用户在导出时单独设置的备份密码保护，与设备绑定密钥无关，因此能够恢复到另一台设备。

## 5. 数据模型

### 5.1 密码记录

每条密码记录包含：

| 字段 | 规则 |
| --- | --- |
| 内部 ID | 系统生成，用户不可编辑 |
| 名称 | 必填 |
| 账号 | 可选 |
| 密码 | 必填 |
| 网址 | 可选 |
| 分类 | 可选，最多一个 |
| 标签 | 可选，可以有多个 |
| 备注 | 可选 |
| 创建时间 | 系统维护 |
| 修改时间 | 系统维护 |

不同记录允许使用相同名称、账号或网址。

### 5.2 分类

分类包含内部 ID 和名称。分类名称去除首尾空格后不允许重复，名称比较不区分大小写。

一条密码记录最多属于一个分类。没有分类的记录统一显示在“未分类”中。

删除分类时只删除分类本身，原有密码记录变为未分类，不删除密码记录。

### 5.3 标签

标签包含内部 ID 和名称。标签名称去除首尾空格后不允许重复，名称比较不区分大小写。

一条密码记录可以包含多个标签。删除标签时只移除标签及其关联，不删除密码记录。

## 6. 手机端功能

### 6.1 密码列表

- 默认按名称排序。
- 每条记录显示名称、账号、分类、标签和密码占位符。
- 所有密码统一显示为 `••••••••`，不通过占位符数量暴露真实长度。
- 点击眼睛图标只显示当前记录的明文密码。
- 再次点击眼睛图标恢复隐藏。
- 点击复制图标可以直接复制账号或密码，不要求先显示密码。
- 离开当前页面或 App 进入后台后，所有已显示密码恢复隐藏。
- 点击记录主体进入详情页，不直接显示密码。

### 6.2 搜索和筛选

搜索范围包括：

- 名称
- 账号
- 网址
- 分类名称
- 标签名称

搜索不匹配密码内容。

用户可以按分类筛选，也可以选择一个或多个标签进一步筛选。选择多个标签时，仅显示同时包含所有已选标签的记录。

### 6.3 新增和编辑

新增和编辑共用一套表单。保存前校验：

- 名称不能为空或只包含空格。
- 密码不能为空。
- 分类必须引用当前存在的分类。
- 标签必须引用当前存在的标签。

保存成功后返回详情或列表，并展示最新数据。保存失败时停留在表单页并保留用户已输入的内容。

### 6.4 删除

删除密码记录前显示确认提示。用户确认后直接永久删除，不进入回收站。

### 6.5 分类与标签管理

支持：

- 创建
- 重命名
- 删除
- 查看关联记录数量

名称为空或与已有名称重复时不能保存，并在对应输入项旁显示原因。

### 6.6 主要页面

首版包含：

- 密码列表
- 密码详情
- 新增/编辑密码
- 分类与标签管理
- PC 访问
- 导入导出与设置

## 7. PC 局域网访问

### 7.1 开启流程

1. 用户在手机进入“PC 访问”页面。
2. 用户点击“开启访问”。
3. App 启动局域网服务并显示访问地址。
4. App 生成并显示随机 6 位访问码。
5. PC 浏览器打开该地址。
6. PC 输入访问码。
7. 验证成功后，访问码立即失效，并建立本次浏览器会话。

验证成功后不要求手机逐项确认 PC 的新增、修改、删除和复制操作。

### 7.2 会话规则

- 同时最多存在一个已认证 PC 会话。
- 已有 PC 连接时，其他设备不能建立新会话。
- 同一页面刷新后可以继续当前有效会话。
- 连续 30 分钟没有任何有效操作后，服务自动停止。
- 手机点击“停止访问”后，会话立即失效。
- 手机网络切换、服务被系统停止或 App 被强制结束后，会话失效。
- 连续 5 次输入错误访问码后，本次访问码失效，用户需要在手机重新开启访问。
- 服务运行期间显示 Android 常驻通知。
- 常驻通知提供“停止访问”操作。

会话凭证只用于本次服务运行周期，服务重启后不得复用。

### 7.3 PC 功能

PC 端支持：

- 查看密码列表和详情
- 搜索名称、账号、网址、分类和标签
- 按分类和标签筛选
- 新增、修改和删除密码
- 创建、重命名和删除分类、标签
- 复制账号和密码
- 点击眼睛图标显示或隐藏密码

PC 端使用与手机端一致的字段校验、分类标签规则和删除确认规则。

PC 端不提供导入、导出和清空全部数据功能。

### 7.4 手机与 PC 的数据关系

PC 的写操作直接提交给手机，由手机业务层校验并写入本地数据库。手机端与 PC 端不维护各自副本。

如果同一记录在手机和 PC 被同时编辑，服务端比较记录版本。较旧版本的保存请求不得静默覆盖新数据，而是提示记录已变化，要求刷新后重新编辑。

### 7.5 连接中断

连接中断后，PC 显示“与手机连接已断开”，不得继续展示新的数据或提交写操作。用户重新开启服务后需要使用新的访问码建立会话。

如果 PC 和手机无法连接，手机页面提供以下检查提示：

- 两台设备是否连接同一 Wi-Fi
- PC 是否已连接手机热点
- 当前网络是否启用了客户端隔离
- 手机 IP 地址是否因网络切换而改变

## 8. 传输与会话安全要求

首版保持简单操作流程，但账号、密码和备注不得以未认证、可被任意篡改的明文业务请求传输。PC 会话需要使用经过访问码认证的加密通信，并校验消息完整性。具体密码学协议和库在实施计划中选定，但不得要求用户安装证书、浏览器扩展或额外 PC 程序。

局域网服务还需要满足：

- 未认证请求不能读取记录数量、名称或其他密码库元数据。
- 访问码验证必须限速。
- 所有数据接口必须独立校验会话，不能只依赖前端隐藏按钮。
- 服务只监听当前局域网访问所需的接口，不主动暴露到互联网。
- 日志中不得记录访问码、会话凭证、账号、密码或备注。

首版面向个人可信 PC。若 PC 本身存在恶意软件、浏览器扩展或剪贴板监控，应用无法保护用户在 PC 上主动查看或复制后的内容。

## 9. 导入与导出

### 9.1 导出

1. 用户在手机选择导出备份。
2. 用户选择文件保存位置。
3. 用户输入并确认备份密码。
4. App 导出全部密码记录、分类和标签。
5. App 生成具有格式版本和完整性校验的加密备份文件。

备份文件使用独立备份密码加密，不依赖当前设备密钥。未完成或失败的导出文件不能作为有效备份保留。

首版不提供选择部分记录导出。

### 9.2 导入

1. 用户选择备份文件。
2. 用户输入备份密码。
3. App 校验密码、文件完整性和格式版本。
4. App 显示待导入的密码记录、分类和标签数量。
5. App 明确提示导入将覆盖当前全部数据。
6. 用户确认后开始导入。
7. 导入在单个事务中完成。
8. 成功后停止当前 PC 会话并重新加载手机数据。

密码错误、文件损坏、版本不支持或写入失败时，不得修改现有数据。

首版不提供合并导入和重复项处理。

## 10. 清空全部数据

手机设置页提供清空全部数据功能。操作需要明确说明将永久删除所有密码、分类和标签，并进行二次确认。

清空成功后停止 PC 会话。首版不提供撤销或恢复，用户只能通过已有加密备份重新导入。

## 11. UI 设计规范

视觉方向采用已确认的简洁风格：

- 白色内容区域
- 冷灰色页面背景
- 单一蓝色作为主要强调色
- 绿色仅用于已连接、成功等状态
- 轻量边框和阴影
- 统一的圆角、标签、按钮和状态样式
- 不使用渐变、装饰性插画和复杂动效

手机端使用卡片式密码列表和底部导航；PC 端使用侧栏、搜索区和表格式密码列表。两端布局根据屏幕尺寸不同，但颜色、间距、信息层级和密码操作图标保持一致。

## 12. 错误处理

- 数据库读取失败时显示错误状态，不展示残缺或未经验证的数据。
- 保存失败时保留表单输入，允许用户重试。
- 删除失败时保持原记录并提示失败。
- 分类或标签已不存在时，保存请求失败并要求刷新数据。
- 网络请求失败时不得假装操作成功。
- 备份密码错误与文件损坏使用不同但不泄露内部细节的提示。
- 导入失败时保持原数据库不变。
- PC 会话失效后，所有后续接口统一返回未授权状态。
- 用户可理解的错误提示使用简体中文，技术细节只写入不含敏感内容的本地诊断日志。

## 13. 验收标准

### 13.1 手机端

- 可以新增包含名称和密码的记录。
- 必填字段为空时不能保存。
- 可以查看、修改和永久删除记录。
- 列表和详情默认遮挡密码。
- 点击眼睛图标后只显示目标记录密码。
- 离开页面或 App 进入后台后密码恢复隐藏。
- 可以复制账号和密码。
- 可以按确认范围搜索。
- 可以创建、重命名和删除分类、标签。
- 删除分类或标签不会删除密码记录。
- App 重启后数据仍然存在并能正常读取。

### 13.2 PC 端

- 手机未开启服务时 PC 无法访问密码库。
- 未输入正确访问码时不能读取任何密码库数据或元数据。
- 正确访问码可以建立一个会话，且访问码随后失效。
- 同时不能建立第二个 PC 会话。
- PC 可以完成已定义的密码、分类和标签操作。
- PC 修改后，手机读取到相同结果。
- 手机修改后，PC 刷新能读取到相同结果。
- 密码默认遮挡，显示和复制行为符合设计。
- 手机停止服务后，原会话立即失效。
- 空闲 30 分钟后服务自动停止。
- 网络变化或服务中止后，PC 得到明确断开提示。

### 13.3 备份

- 导出文件不包含可直接读取的明文密码。
- 正确备份密码能够完整恢复密码、分类和标签。
- 错误备份密码不能导入。
- 文件损坏不能导入。
- 导入失败不改变现有数据。
- 导入成功后旧 PC 会话失效。

### 13.4 隐私与安全

- 数据库、备份和局域网会话符合本设计的加密要求。
- App 没有业务请求发送到互联网。
- PC 页面不持久化密码库。
- 未认证接口不能泄露密码库元数据。
- 日志和错误信息不包含敏感字段。
- Android 系统自动备份不包含密码数据库或密钥。

## 14. 实施阶段拆分建议

本设计适合作为一个产品规格，但实现时应分阶段交付：

1. Android 项目骨架、本地数据库和数据模型。
2. 手机端密码 CRUD、搜索、分类和标签。
3. 密码显示与复制规则、设置与清空数据。
4. 加密备份导入导出。
5. 局域网服务、访问码和会话管理。
6. PC Web 页面及手机/PC 数据冲突处理。
7. 安全加固、异常场景和完整验收测试。

每个阶段必须保持可构建、可测试，不提前加入首版非目标功能。

## 15. 构建与安装包交付

首版保持 Android 原生实现，不为云构建改写成 Expo 或 React Native。

使用 GitHub Actions 完成 Android 云构建：

- 工作流只允许手动触发，避免未完成代码自动生成安装包。
- 构建顺序固定为核心单元测试、Android 单元测试、静态检查、APK 构建。
- 任一测试或检查失败时不得上传 APK。
- APK 作为 GitHub Actions Artifact 提供下载，不自动公开发布到应用商店或 GitHub Release。
- 可安装版本使用固定的应用签名密钥，保证后续版本能够覆盖安装。
- 签名文件、密钥密码、别名和别名密码只存放在 GitHub Secrets，不提交到仓库，也不得写入构建日志。
- 仓库中只保存从 Secrets 恢复临时签名文件的构建配置；构建结束后由临时运行环境自动销毁。
- 用户在真实手机安装并试用 APK 后，实际设备问题继续进入缺陷修复和回归测试流程。
